# Release v0.4

## Problem addressed

v0.3 added a structured Helvetia banking domain, but `/ask` still answered from a public multi-bank `.txt` corpus in ChromaDB. That stack could not share versioned policy metadata, active/superseded filters, or hybrid search with Postgres.

## User-visible capability

- Fictional Helvetia internal policy corpus (Markdown + YAML frontmatter) covering KYC, AML, transfers, restrictions, complaints, SLAs, communication, and related procedures
- Policy ingest into PostgreSQL + pgvector (`POST /ingest` or CLI), with active / superseded / draft versions
- Hybrid retrieval (vector + Postgres FTS, merged with RRF); default search uses **active** documents only
- `/ask` grounded on Helvetia policies with department, document title, and source attribution
- Helvetia-focused chat UI (Compose Vite service locally; Vercel in production)
- Retrieval evaluation golden set (≥40 cases) plus Compose `test` / `eval` profiles
- Local one-command stack: API (migrate on start), Postgres + pgvector, frontend, pgAdmin

## Architecture changes

- Knowledge tables and Alembic revisions for pgvector embeddings and FTS (`content_tsv` + GIN)
- `app/retrieval/` hybrid baseline; ChromaDB and the public bank corpus removed from the operational path
- `app/rag/policy_registry.py` and `policy_ingest.py` for validated policy load and upsert
- ADR-002 (pgvector) and ADR-003 (hybrid retrieval)
- Compose frontend service and QA profiles (`test`, `eval`)

## Validation performed

- Unit and API tests (including policy registry, hybrid RRF, eval case schema)
- Retrieval eval suite: Recall@k / MRR / superseded and draft traps (Compose `--profile eval`)
- Local Compose smoke: migrate → seed → ingest → UI `/ask`

## Known limitations

- Hosted production cutover (Neon/`DATABASE_URL` on Render, re-ingest after promote to `main`) is a follow-up deploy step — not part of this `dev` release tag
- No RRF score floor yet; abstention is “no hits” (plus intent out-of-scope / meta paths)
- Role/jurisdiction filters exist in retrieval but are not yet exposed on the public `/ask` API
- No authentication/authorization on API routes yet
- LLM and embedding calls require a configured OpenAI API key
