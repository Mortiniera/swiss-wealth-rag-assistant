# Release v0.5

## Problem addressed

v0.4 grounded `/ask` on Helvetia policies, but the product still presented as a chat-first demo. Operators could not browse the structured client book or policy catalog as primary work surfaces, and there was no honest demo identity for role-scoped reads.

## User-visible capability

- Helvetia **operations workspace** UI: brand chrome, Clients / Policies nav, docked policy assistant (no longer a chat landing page)
- Client directory with search, All / Scenarios scope, column sort/filter, and pagination
- Client detail: profile/KYC, accounts & restrictions, transactions, service requests, interactions
- Policy catalog and policy detail reader (active Helvetia documents)
- **Demo Act-as identity** (`X-Helvetia-Actor`): pick a seed employee; honest “demo identity” banner — not login
  - Relationship managers see an **assigned** client book; Client Service / Compliance see the **full** book
  - Policies and `/ask` retrieval respect document `allowed_roles`
  - Panel order for client detail comes from the workspace API (presentation preference)
- Selected-client context on the assistant dock (prompt enrichment + UI hint)
- README screenshots of the live ops surfaces

## Architecture changes

- Frontend ops shell (`frontend/`): AppShell, workspaces, assistant dock, Act-as picker
- `GET /actors`, `GET /actors/{code}/workspace`
- Optional actor dependency on `/clients`, `/policies`, and `/ask`
- Role-aware client listing and policy catalog filtering in service layer
- Docs: system architecture route table; operations UI assets under `docs/assets/ops-*.png`

Incremental tags on the feature branch: `v0.51` (shell) → `v0.52` (directory/profile) → `v0.53` (activity panels) → `v0.54` (policies + column filters) → `v0.55` (Act-as + scoping).

## Validation performed

- Unit and API tests (including actors API)
- Local Compose smoke: API + frontend; Act-as RM vs Compliance client counts; unassigned client returns 404 for RM
- Frontend production build (`tsc` + Vite)

## Known limitations

- Demo actor header is **not** authentication or full RBAC — governance lands in a later major
- No SSO / session login
- No tool-calling agent loop (workspace tools are a later major)
- No write endpoints, email draft/approve, or restriction lifts
- Hosted promote (`dev` → `main` / Render / Vercel) is a separate deploy step
