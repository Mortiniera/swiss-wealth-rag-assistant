# Release v0.3

## Problem addressed

The prior release focused on document-centric Q&A. It did not provide a structured banking domain model or API surface to verify client operational cases.

## User-visible capability

- PostgreSQL-backed synthetic Helvetia domain
- Deterministic seed and reset workflow
- Fifteen curated scenario clients (`CLI-SCEN-*`) for repeatable demos
- Read-only client APIs for profile, accounts, transactions, interactions, and service requests
- Docker Compose setup running API, Postgres, and pgAdmin together
- Starter Postman collection and environment for local API testing

## Architecture changes

- SQLAlchemy model package split by concern (`people`, `accounts`, `compliance`, `operations`)
- Alembic baseline migration for the domain schema
- Modular seed architecture:
  - base synthetic generation (`app/database/seed.py`)
  - scenario builders and scenario cases
  - scenario orchestrator (`apply_scenario_overrides`)
- Service layer for read APIs (`app/services/client_read.py`)
- Typed response schemas for client APIs (`app/schemas/clients.py`)

## Validation performed

- Seeder smoke tests with deterministic scenario verification
- API smoke checks for `GET /clients/CLI-SCEN-01` and related endpoints
- Postman collection import and variable-based request coverage
- Automated tests for the clients router response shapes and error path

## Known limitations

- No authentication/authorization on API routes yet
- API is read-only (no mutation endpoints for operational actions)
- LLM-backed flows depend on runtime API key configuration
