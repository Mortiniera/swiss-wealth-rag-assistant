# Release v0.2.0

## Problem addressed

The v0.1.0 MVP answered single-turn questions over a small document corpus via API only. It lacked a chat UI, multi-turn conversation, intent routing, and a structured evaluation path.

## User-visible capability

- React + Vite chat UI with source cards and citation rendering
- Multi-turn conversation support on `POST /ask`
- Intent classification (`RAG_QUERY`, `ASSISTANT_META`, `OUT_OF_SCOPE`)
- Query rewriting for follow-up retrieval questions
- Expanded Swiss wealth document corpus with institution metadata
- Structured logging across ingest, retrieval, and generation
- Evaluation script (`eval/run_eval.py`) with golden questions
- CORS for local frontend and Vercel deployment

## Architecture changes

- Linear orchestrator in `app/assistant/` (intent → rewrite → retrieve → generate)
- Enriched source metadata (institution, document title, chunk score)
- Frontend as thin client; backend owns the full pipeline
- Test suite covering intent, query rewriting, API validation, and RAG responses

## Design decisions

- Intent routing before retrieval to avoid wasted embedding/LLM calls on meta and out-of-scope questions
- Query rewriting only when conversation history exists and intent is `RAG_QUERY`
- Institution metadata attached at ingest time for richer source attribution in the UI

## Alternatives considered

- Frontend-driven retrieval (rejected — backend owns pipeline for consistency and future agent extension)
- LangGraph or multi-agent orchestration (deferred — explicit linear flow sufficient for document Q&A)

## Evaluation results

- `eval/run_eval.py` with `eval/questions.json` for retrieval and fallback checks
- Pytest suite for intent classification, query rewriting, and API behaviour

## Failures and debugging notes

- Fixed NameError in fallback logging on low-relevance questions
- CORS configuration required for Vercel frontend origin

## Security considerations

- No authentication on API (demo/portfolio scope)
- CORS restricted to known frontend origins
- Still no client or account data — public document corpus only

## Known limitations

- Still document Q&A only — no PostgreSQL, synthetic banking domain, or agent tools
- ChromaDB remains the vector store (pgvector cutover planned for v0.4)
- Permissions and audit trails not yet implemented

## Next release

v0.3 — synthetic banking domain with PostgreSQL, deterministic seed data, curated scenarios, and read-only client APIs.
