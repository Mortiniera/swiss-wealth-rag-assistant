# Release v0.7

## Problem addressed

v0.6 added read-only client tools and a bounded workflow, but tool selection was still batch-oriented, policy retrieval always ran again in generate, and the loop could finish before verifying what the user assumed. Bulk seed data could also disagree with the workspace UI (e.g. restricted accounts without restriction rows).

## User-visible capability

- **Structured ReAct loop**: each turn chooses `call_tool`, `search_policies`, or `finish` (one client tool or one policy search per round, hard cap on rounds)
- **Verification-first planning**: parse question vs asserted facts; verify with tools before answering; honest answers when an assertion is false or not on file
- **Policy search in the loop**: hybrid retrieval during the agent run; generate reuses those hits instead of blind double-retrieve
- **`search_internal_policies`** on the agent tool catalog (alias for loop policy search with `policy_query`)
- **`get_account_summary`** holdings snapshot for portfolio / AUM questions
- **Restriction alignment**: bulk seed, read APIs, tools, and workspace UI agree on restricted accounts
- **Scenario suggested prompts** for all 15 `CLI-SCEN-*` clients
- **Evidence chips** extended for holdings and interaction history sources

## Architecture changes

- `app/agent/turn_decision.py`, `nodes/agent_turn.py`, `nodes/search_policies.py`
- `AgentState`: `last_decision`, `policy_hits`, `policy_queries`, `round_trace`
- `routing.py`: `STEP_SEARCH_POLICIES` between turn planner and rewrite
- `facts.py` / `generator.py`: verification-aware case triage and loop policy hits
- `seed.py`: `_seed_restrictions` for bulk clients; coherence tests for scenarios and restrictions

Incremental tags on the feature branch: `v0.71` (account summary) → `v0.72` (loop skeleton) → `v0.74` (structured ReAct + policy search + restriction alignment) → `v0.75` (catalog `search_internal_policies`).

## Validation performed

- Unit and integration tests: turn decisions, workflow routing, tool payloads, facts/evidence, seed restriction coherence, scenario book QA (`CLI-SCEN-01` … `15`)
- Local Compose rebuild + `scripts/seed_db.py` after seed changes
- Manual ops checks on curated scenarios and bulk clients (Adrian Baumann restriction case)

## Known limitations

- Holdings exist in tools but not yet in the workspace UI panel
- Client directory “open items” badge still KYC-only (ignores pending txns, restrictions, open SRs)
- Bulk clients remain statistically random except restriction/KYC coupling; curated stories are `CLI-SCEN-*`
- Demo Act-as is not full enterprise RBAC
- No write actions, email draft/send, Langfuse, or MCP
- Production promote (`dev` → `main` / Render / Vercel) is a separate deploy step
