# Release v0.1.0

## Problem addressed

Build a credible document-only RAG assistant over public Swiss wealth management content — ingest, retrieve, and generate grounded answers without hallucinating when evidence is weak.

## User-visible capability

- Ingest `.txt` documents from `data/documents/`
- Embed and store vectors in ChromaDB via LlamaIndex
- Answer questions with grounded generation and source attribution
- Refuse to hallucinate when retrieval confidence is below threshold
- Auto-ingest on startup when the vector index is empty
- Docker support and Render deployment

## Architecture changes

- FastAPI API with `/ingest`, `/ask`, `/health`
- ChromaDB persistent vector store
- OpenAI embeddings (`text-embedding-3-small`) and configurable LLM
- LlamaIndex for document loading, chunking, and retrieval

## Design decisions

- Local ChromaDB for simplicity and zero external DB dependency at MVP stage
- Fixed fallback message when best retrieval score is too low — no LLM call on weak evidence
- Startup auto-ingest to keep Render deployment usable without manual `/ingest`

## Alternatives considered

- Hosted vector DB (deferred — added operational complexity without proving RAG value first)
- Multi-turn conversation (deferred to v0.2.0)

## Evaluation results

Manual smoke tests via Swagger and curl; no automated eval suite in this release.

## Failures and debugging notes

- Render ephemeral filesystem requires re-ingest after redeploy if vector store is wiped

## Security considerations

- OpenAI API key via environment variables only
- Public read-only document corpus — no client or account data

## Known limitations

- Document Q&A only — no structured banking data or agent workflows
- ChromaDB on local/ephemeral filesystem
- Single-turn questions only
- Small initial document corpus

## Next release

v0.2.0 — conversational assistant polish with React UI, intent routing, query rewriting, expanded corpus, and evaluation tooling.
