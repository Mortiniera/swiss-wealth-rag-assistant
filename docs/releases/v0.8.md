# Release v0.8

## Problem addressed

v0.7 made agent decisions opaque outside logs. Operators and engineers could not see tool rounds, retrieval quality, LLM cost, or stop reasons without reproducing a case locally.

## User-visible capability

![Dev UI — View Langfuse trace link](../assets/obs-trace-link-dev.png)

![Langfuse — end-to-end ask trace](../assets/obs-langfuse-trace-detail.png)

- **Opt-in Langfuse** — enable with `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, optional `LANGFUSE_BASE_URL`; missing keys → no behaviour change
- **One trace per `/ask`** — root chain with spans for classify, agent turns, tools, policy search, rewrite, generate
- **Per-tool spans** — each read-only tool call with `ok` / `error_code` and `client_ref`
- **LLM generation spans** — model, latency, token usage on classify, agent turn, rewrite, and answer steps
- **Log ↔ trace correlation** — `trace_id` on workflow completion logs (same id as in Langfuse)
- **Dev-only trace link** — `trace_url` on `/ask` when `APP_ENV=dev`; production (`APP_ENV=prod`) omits the field entirely

## Architecture changes

- `app/observability/` — `langfuse_client.py` (init), `tracing.py` (observe, generations, `dev_trace_url`)
- `app/config.py` — Langfuse credentials + `APP_ENV`
- `app/agent/orchestrator.py` — step spans around the bounded workflow
- LLM call sites instrumented: `intent.py`, `agent_turn.py`, `query_rewriter.py`, `generator.py`
- `run_tools.py` — per-tool child spans
- `AskResponse.trace_url` optional; `response_model_exclude_none` on `/ask`
- Frontend: “View Langfuse trace” under assistant messages when API returns `trace_url`

Incremental tags on the feature branch: `v0.81` (init facade) → `v0.82` (step traces) → `v0.83` (tool + generation spans) → `v0.84` (dev trace links).

## Enable locally

```bash
# .env
APP_ENV=dev
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_BASE_URL=https://cloud.langfuse.com   # or https://us.cloud.langfuse.com
```

Rebuild the API container after changing env vars. Ask a question in the ops assistant — **View Langfuse trace** appears under the answer in dev.

## Production (Render)

- Set `APP_ENV=prod` (required — suppresses `trace_url` in API responses)
- Langfuse keys optional: tracing still runs when set; users never see trace links in the UI

## Validation performed

- Unit tests for observability facade, spans, `APP_ENV` gating, and existing agent workflow suite
- Manual Compose run: `/ask` on `CLI-SCEN-01` transfer triage — trace visible in Langfuse with tool loop, generations, and metadata (`intent`, `tool_round`, `stop_reason`, `client_ref`)

## Known limitations

- No governance matrix, email/MailHog, or MCP (planned v0.9+)
- No full prompt bodies in traces (PII hygiene)
- Trace links require Langfuse project access (private traces)
- Eval score export to Langfuse deferred
